# 헤더·푸터와 브랜딩 페이지

이슈: #16

## 요구사항과 시나리오

- S1. 모든 화면(홈 랜딩 포함)의 헤더는 로고, 가운데 메뉴(모의면접, 질문 아카이브, 경험 정리), 알림·내 정보 아이콘으로 구성한다. 지금 보고 있는 메뉴는 진하게 표시한다.
- S2. 화면을 아래로 스크롤해도 헤더가 화면 위에 붙어 있다.
- S3. 푸터는 로고와 서비스 소개, 주요 서비스 링크(모의 면접, 질문 아카이브, 마이페이지), GitHub 링크, 저작권, 개발자 이름을 보여 준다. 배경색을 칠하지 않아 놓인 화면의 배경을 따라간다.
- S4. 면접 준비(`/interviews/new`), 면접 진행(`/interviews/[id]`), AI 분석(`/interviews/[id]/analyzing`), 관리자 화면(`/admin/**`)에는 서비스 푸터가 없다.
- S5. 로컬·테스트 서버에서는 푸터 맨 아래에 데이터 모드·역할 전환기가 보인다. 관리자 화면에는 전환기만 있는 개발용 푸터가 붙는다. 운영 환경에서는 전환기도, 관리자 화면의 개발용 푸터도 보이지 않는다.
- S6. 브랜딩 페이지(홈 랜딩 페이지, `/`)의 디자인을 수정한다. 디자인이 확정되면 시나리오를 채운다.

## 정한 것

- 푸터를 뺄 화면은 `(interview)` 라우트 그룹에 둔다. `(site)` 레이아웃은 모든 화면에 푸터를 붙이므로, 그룹을 나누는 것 말고는 일부 화면만 뺄 방법이 없다. `(interview)` 화면은 `<Main>`을 직접 그린다.
- 관리자 레이아웃은 `<AppFooter switcherOnly />`로 전환기만 있는 푸터를 그린다. 세션을 불러오지 못했을 때도 관리자 화면에서 데이터 모드를 되돌릴 수 있게 하기 위해서다.
- 데이터·역할 전환기는 개발 중에만 쓰는 임시 기능이다. `SiteFooter`의 `children` 자리에만 들어가므로, 없앨 때는 `AppFooter`에서 `DemoSwitcher`를 넘기지 않으면 된다.
- 홈과 로그인 배경도 같은 헤더(`TopBar`)를 쓴다. 헤더는 히어로 안이 아니라 페이지 맨 위에 둔다. sticky 요소는 부모 밖으로 따라오지 못해서, 히어로 안에 두면 히어로를 지나면서 사라지기 때문이다. 사진 위에 깔리던 홈 전용 헤더(`SiteHeader`)와 서울 시계는 지웠다. 비회원도 로그인 버튼 대신 알림·내 정보 아이콘을 보고, 누르면 로그인으로 간다.
- 경험 정리 메뉴는 `/experiences`로 간다(고침 #17: 화면 이름에 맞춰 "이력 관리"에서 바꿈). 화면은 [경험 정리](document/experiences.md)다.
