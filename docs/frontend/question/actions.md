# 문제은행 변경 액션 연결

[문제은행 청사진](../../backend/question/README.md)의 QB-11이다. [조회 연결](archive.md)의 인증·응답 변환을 재사용하며 화면 URL과 기존 디자인을 유지한다. 실제 계정의 브라우저 흐름과 관리자·AI 전체 연계는 QB-12에서 확인한다.

## 입력과 저장

등록·수정 폼은 서버 액션으로 `GET /api/v1/categories`를 읽고 CS 분류의 실제 ID와 이름을 사용한다. ID는 문자열로 유지한다. 조회 중·실패·빈 분류 상태에서는 저장하지 못하게 하고 실패 시 다시 불러올 수 있다. 기존 개인 화면의 이름 기반 데이터는 조회한 분류 목록 안에서만 ID로 대응시킨다. 실제 API 모드에 한글 분류 상수를 대신 저장하지 않는다.

서버 액션은 categoryId와 trim한 질문을 검증한 뒤 `{categoryId,content}`만 보낸다. 질문은 10~200 Unicode code point다. 작성자·승인 상태·출처·답안 등은 보내지 않는다. CS 분류의 존재 여부와 수정·삭제 권한은 백엔드가 최종 판정한다.

| 동작 | 요청 | 화면 반영 |
| --- | --- | --- |
| 등록 | `POST /api/v1/learning/questions` | 201의 문자열 ID를 유지하고 `/archive/{id}` 승인대기 상세로 이동 |
| 수정·재제출 | `PATCH /api/v1/learning/questions/{id}` | 같은 ID를 유지하며 상세 재조회. 반려 사유는 서버의 PENDING 응답에서 해제 |
| 삭제 | `DELETE /api/v1/learning/questions/{id}` | 빈 204를 성공으로 처리하고 안전한 내부 next 주소로 이동 |
| 좋아요 등록·취소 | `POST/DELETE /api/v1/learning/questions/{id}/likes` | 서버의 likeCount/isLiked를 사용하고 현재 화면 갱신 |
| 신고 | `POST /api/v1/learning/questions/{id}/reports` | 신고 상태와 canReport를 다시 조회 |

API 모드의 변경 요청은 기존 전체 배열을 GET해 권한을 추정하지 않는다. 회원 검증과 Bearer 전달 후 해당 변경 API를 호출한다. 잘못된 쓰기 ID는 URL로 변환하기 전에 거절한다. 본인 미승인·승인 상태·타인·중복 신고 등은 백엔드 오류를 그대로 사용한다.

## 신고 유형과 실패

화면의 다섯 문구는 각각 WRONG_QUESTION·WRONG_ANSWER·DUPLICATE·INAPPROPRIATE·ETC로 변환한다. 임의 문구는 보내지 않는다. 상세는 선택 값이며 trim 후 300 code point까지 허용한다. 서버에는 `{reasonType,detail}`만 전달한다.

폼 오류와 400/403/404/409는 입력을 유지한 채 안내한다. 인증 리다이렉트와 알 수 없는 서버 오류는 정상 성공으로 바꾸지 않는다. 실제 API 실패를 목업으로 대체하거나 POST를 자동 재시도하지 않는다. 등록의 멱등 키는 없으므로 요청 결과가 불명확할 때 자동 중복 등록을 만들지 않는다.

등록 폼과 좋아요 버튼은 진행 중 중복 전송을 막는다. 좋아요는 낙관적으로 표시한 뒤 서버 집계와 새 조회 결과를 따른다. 실패하면 기존 상태로 돌아가 오류를 표시한다. 성공한 변경만 `/archive`, 해당 상세, `/my/questions`, `/my/likes`, `/my`를 재검증하고 현재 화면을 갱신한다. 개인 API 자체가 아직 연결되지 않은 범위는 별도 담당 작업으로 남는다.

## 유사 질문 후보 기준

입력 전체를 검색어로 보내거나 전체 아카이브를 다운로드하지 않는다.

1. 입력의 양 끝 공백을 정리하고 최대 200 code point를 사용한다. 4자 미만은 조회하지 않는다.
2. 기존 일반 질문 문구와 구두점을 정리하고, 조사 등을 제거한 2자 이상 단어 중 가장 긴 단어를 선택한다. 길이가 같으면 앞의 단어를 사용한다.
3. 검색어를 최대 100 code point로 제한해 CS·최신순·첫 페이지·pageSize=20으로 기존 목록 API에 요청한다. 선택 분류에 한정하지 않는다.
4. 받은 후보에서 기존 두 글자 조각 유사도 기준으로 전체 입력과 비교하고 한 개만 안내한다.

후보 밖의 유사 질문까지 찾는 것을 보장하지 않으며 등록을 차단하는 중복 검사로 쓰지 않는다. 검색 실패는 후보 없음과 구분해 안내하지만 질문 저장을 막지는 않는다. 입력이 바뀌거나 폼이 닫히면 이전 요청의 늦은 결과를 표시하지 않는다.

## 목업과 남은 범위

목업 분기는 기존 표시 이름 기반 저장소에 분류 ID를 대응시킨다. 본인 PENDING/REJECTED만 수정·삭제하고 공개 질문만 좋아요·신고하도록 실제 정책과 맞춘다. 기존 목업의 승인대기 10개 제한은 목업에만 남으며 백엔드 정책으로 추가하지 않는다.

내 질문·좋아요 전체 목록과 면접 결과 질문의 좋아요는 별도 회원·면접 계약이다. 공개 목록 첫 페이지로 대체하지 않는다. 실제 카카오 계정 로그인과 관리자 승인·반려·AI 답안 생성 흐름의 브라우저 확인은 QB-12에 남는다.

검증은 프론트 단위 테스트 343개와 typecheck·lint·structure·production build가 통과했다. 요청 테스트는 실제 HTTP adapter에 고정 fetch 응답을 제공해 메서드·URL·본문·Bearer·204·오류 전파를 확인하며, 서버 액션 테스트는 ID 반환·서버 집계·재검증·이동·입력 오류를 확인한다. 실제 브라우저·카카오 계정 검증 결과로 해석하지 않는다. 백엔드 코드는 변경하지 않아 QB-10의 테스트 614개 및 build 통과 결과를 재사용한다.
