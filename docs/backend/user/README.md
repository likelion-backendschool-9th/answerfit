## 정한 것

- 로그인 상태는 백엔드가 발급한 JWT 액세스 토큰으로 유지한다. 서버 세션은 쓰지 않는다. 프론트 서버가 토큰을 httpOnly 쿠키에 두고 백엔드를 부를 때 `Authorization: Bearer`로 보낸다. (#12, 2026-11-26)
- 토큰은 HS256으로 서명하고, 비밀키는 환경 변수 `JWT_SECRET`으로 받는다. 리프레시 토큰은 아직 없다. (#12, 2026-11-26)
- 소셜 로그인의 인가 코드는 프론트가 받고, 카카오와의 토큰 교환은 백엔드가 한다. 클라이언트 시크릿은 백엔드에만 둔다. (#12, 2026-11-26)
- 소셜 계정은 제공자의 회원번호(`provider_user_id`)로 찾는다. 이메일은 바뀔 수 있어 식별에 쓰지 않는다. (#12, 2026-11-26)
- 같은 이메일의 회원이 이미 있으면 소셜 계정을 자동으로 연결하지 않는다. 남의 계정에 들어가는 사고를 막기 위해서다. 연결은 계정 설정에서 로그인한 회원이 직접 한다. (#12, 2026-11-26)
- 소셜 가입은 제공자가 인증했다고 표시한 이메일만 받는다. (#12, 2026-11-26)
- 이용 정지된 회원은 로그인할 때 막는다. 이미 발급한 토큰은 만료될 때까지 쓸 수 있다. (#12, 2026-11-26)
- `/api/auth/**` 말고는 모든 API가 토큰을 요구한다. 비회원도 써야 하는 API는 `SecurityConfig`의 공개 경로에 추가한다. 새 API가 실수로 열리지 않게 하기 위해서다. (#12, 2026-11-26)
- 카카오 같은 외부 호출은 트랜잭션 밖에서 하고, 연결·응답 시간 제한을 둔다. 외부 서비스가 느려도 DB 커넥션을 잡고 기다리지 않게 하기 위해서다. (#12, 2026-11-26)
- 오류 응답은 `{ "code": "...", "message": "..." }`이다. `message`는 화면에 그대로 보여도 되는 문장이다. (#12, 2026-11-26)

## 데이터 구조

- `users`: 이메일(로그인 아이디), 비밀번호 해시(소셜 전용 회원은 NULL), 닉네임, 역할(`USER`·`ADMIN`), 상태(`ACTIVE`·`SUSPENDED`), 탈퇴 일시
- `user_social_accounts`: 회원 하나에 제공자마다 하나. `(provider, provider_user_id)`가 유일하다.

## 아직 정하지 않은 것

- [ ] 리프레시 토큰과 로그아웃할 때 토큰을 무효로 만드는 방법
- [ ] 정지된 회원의 이미 발급된 토큰을 바로 끊을지
- [ ] 관리자 권한 확인. 토큰에 `role` 클레임은 있지만 Spring Security 권한(`GrantedAuthority`)으로 연결하지 않았다. 관리자 API를 만들 때 `JwtAuthenticationConverter`를 설정한다.
- [ ] 탈퇴한 회원이 같은 소셜 계정으로 다시 가입할 때. `(provider, provider_user_id)` 유일 조건이 탈퇴 회원의 기록에도 걸린다. 지금은 "탈퇴한 계정"으로 안내하고 막는다.
- [ ] GitHub·구글 로그인, 계정 설정의 소셜 계정 연결·해제
